# AI 网关架构说明

## 模块边界

AI 模块采用管理面与流量面分离的结构：

- `api`、`router`：只负责 HTTP 参数解析、协议入口和管理路由。
- `provider_service`、`channel_service`、`access_token_service`、`proxy_service`：负责单一聚合根的校验和持久化。
- `gateway_protocol`：OpenAI 与 Anthropic 请求、响应的协议转换。
- `gateway_provider`：根据供应商协议创建 GoAI `LanguageModel`，新增兼容厂商时优先扩展此处。
- `gateway_routing`：加载不可变路由快照，执行模型过滤、优先级和权重选择。
- `gateway_runtime`：通过 `RateLimiter`、`CircuitBreaker` 接口维护单实例 RPM/TPM 窗口和渠道熔断状态，默认实现使用 `sync.Map` 与原子计数。
- `ai_store`：抽象管理面 CRUD、查询和分页能力，业务服务不直接依赖 `global.DB`。
- `gateway_repository`：抽象流量面的鉴权、路由、额度、日志和健康检查持久化能力。
- `call_log_sink`：使用有界队列、批量写入和定时刷新异步落库调用日志。
- `credential_vault`：使用 AES-256-GCM 加密渠道 API Key 和代理密码，并兼容旧明文数据迁移。
- `credential`：负责访问 Token 生成、哈希、管理面脱敏和错误信息清洗。
- `billing`：统一 OpenAI、Anthropic 及 GoAI 用量，并维护调用日志与 Token 用量账本。
- `validation`：统一保存校验和流量请求边界。

HTTP API 与服务通过构造函数注入依赖。默认依赖只在 `service/enter.go` 组合根中绑定 GORM、本地运行时组件和异步日志组件，便于测试替换及后续扩展。

## 路由策略

路由目录以启用的供应商、渠道和代理为输入，生成短周期内存快照。管理面修改配置后会主动失效快照，异常情况下最长 5 秒自动刷新。

请求只会进入当前模型可用的最高优先级渠道组，再在同优先级渠道中按权重选择。连续失败 5 次的渠道熔断 1 分钟；熔断窗口结束后失败计数重置。RPM/TPM 使用本地内存分钟桶和原子计数，不依赖 Redis。

## 安全边界

- 网关访问 Token 使用 `crypto/rand` 生成，数据库仅保存 SHA-256；明文只在创建或主动轮换时返回一次。
- 旧版本明文 Token 仍可调用，并在首次成功鉴权后自动迁移为哈希。
- 管理查询不会返回 Token、渠道 API Key 或代理密码，更新时传入 `********` 会保留原凭据。
- 渠道 API Key 和代理密码使用 AES-256-GCM 加密后存储，密文带有 `enc:v1:` 版本前缀。
- 配置主密钥后，读取旧明文渠道或代理配置时会自动迁移为密文；已加密数据在缺少或使用错误主密钥时拒绝解密，不会降级为明文处理。
- OpenAI 与 Anthropic 流量入口限制请求体、消息数、工具数和内容块数。
- 日志和错误响应会清理常见 Authorization、X-API-Key 与 API Key 内容。
- 供应商 BaseURL 禁止携带 URL 用户名和密码，并限制为 HTTP/HTTPS。

生产环境必须通过 `APIPIG_AI_ENCRYPTION_KEY` 注入至少 32 字符的独立主密钥，新建或轮换上游凭据时必须配置该密钥。不得复用 JWT 签名密钥。主密钥在首次成功使用后由进程缓存，轮换主密钥需要完成数据迁移并重启应用；当前不支持运行时热轮换。

## 调用日志与关闭流程

调用日志先进入有界内存队列，再按批量大小或刷新间隔写入数据库。队列满时同步写入，批量写入失败时回退为逐条写入，避免静默丢失。应用关闭时先停止 Fiber 接收请求，再在 5 秒超时内排空并关闭日志队列。

默认配置：

```yaml
ai:
  log-queue-size: 2048
  log-batch-size: 100
  log-flush-interval-ms: 1000
```

## 计费与用量

用量与金额账本保持当前项目的整数存储方式：

- 金额账本使用微美元整数，`1 USD = 1,000,000 microUSD`，避免额度比较和累计扣费产生浮点误差；原有美元字段继续作为管理 API 展示兼容字段。
- 供应商不再维护 Token 单价；渠道号池按上游模型配置输入、输出、缓存读写 Token 价格以及输入、输出图片单价。Token 价格支持 `USD / Token` 与 `USD / 1M Token` 两种明确单位；历史未标单位且全部非零 Token 单价不超过 `0.0001` 的规则按 `USD / Token` 兼容读取，保存后会写入明确单位。
- 渠道账户维护网关模型到上游模型的映射，同一号池下不同 API Key 可具有不同的模型能力。
- 计价和账户映射随路由目标缓存，渠道或账户保存、删除、启停后立即失效；调用日志保存命中模型和价格快照。
- 渠道支持 `costMultiplier`。调用日志同时快照标准成本、倍率和有效成本，后续修改渠道倍率不会污染历史账单。
- OpenAI `cached_tokens` 会从普通输入 Token 中扣除后单独计费；Anthropic 的缓存读取和缓存创建用量分别记录。
- 推理 Token 单独记录用于分析，但通常已经包含在输出 Token 中，不重复收费。
- 只有成功调用累计 Token 用量和有效成本；失败调用只累计失败次数。额度在请求开始前检查，因此与 `ccLoad` 一样允许单个已开始请求使额度略微超出上限。
- Access Token 累计成功/失败次数、输入/输出/推理/缓存 Token、最后使用时间和有效成本。
- 数据库自动迁移会把旧 `quota_amount`、`used_amount` 回填到微美元字段，不影响已有 Token。

## 扩展新供应商

1. 在 `gateway_provider.go` 增加协议别名和 GoAI Provider 构造器。
2. 只有上游协议无法映射到 `provider.GenerateParams` 时，才扩展协议转换层。
3. 在管理端供应商配置中填写协议、BaseURL 和模型集合，不应在业务代码中硬编码模型名。
4. 为普通响应、流式响应和工具调用增加契约测试。

## 当前约束与演进方向

- RPM、TPM 和熔断状态按用户要求保存在本地进程内，不引入 Redis。该模式适合单实例，或可接受每实例独立额度的多实例部署；多副本不会形成全局严格限额。
- Token 成本累计使用数据库原子表达式更新，多实例不会发生读改写覆盖；请求前额度判断仍允许并发中的少量超额请求。
- `AiService` 保留为默认应用组合实例，但 API、CRUD 服务、网关仓储、凭据仓库、限流器、熔断器和日志写入器均已支持接口或构造函数注入。
- `global.DB` 仅在默认组合根、兼容零值服务和默认网关仓储回退中绑定；业务方法不再直接访问全局数据库。
- 路由快照当前按固定 TTL 刷新；配置规模扩大后可改为版本号或事件驱动刷新。
- AES-GCM 主密钥目前由环境变量管理；更高安全等级部署可将 `CredentialVault` 替换为云 KMS 或 Vault 信封加密实现。
